# Week 08 — 索引、事务与锁

> 主线项目：并发安全下单。每天用 EXPLAIN、事务日志和两个数据库会话验证结论。

## Day 1 — B+Tree 与索引

### 学习
- 索引减少扫描；B+Tree 适合范围与排序。
- 聚簇索引、二级索引、回表、覆盖索引。

### 练习
为商品状态、价格查询建索引；用 EXPLAIN 对比有无索引。

### 验收
索引列顺序有查询依据；能解释额外索引的写入成本。

## Day 2 — 联合索引

### 学习
- 最左前缀、等值/范围条件、排序方向。
- 选择区分度高且符合访问模式的前缀。

### 练习
为 `user_id + status + created_at` 的订单列表设计索引并测试三种查询。

### 验收
不把联合索引当成独立单列索引的简单相加。

## Day 3 — EXPLAIN

### 学习
- type、possible_keys、key、rows、Extra。
- 估算行数不等于实际行数；先观察再判断。

### 练习
记录全表扫描、索引扫描、覆盖索引的执行计划和差异。

### 验收
能提出基于计划的优化，而非只凭“加索引”。

## Day 4 — ACID 与事务边界

### 学习
- 原子性、一致性、隔离性、持久性。
- 一个下单事务包含扣库存、订单和订单项写入。

### 练习
模拟明细写入失败，验证前面的库存更新回滚。

### 验收
事务不跨越外部 HTTP 调用；提交点唯一明确。

## Day 5 — 隔离级别与 MVCC

### 学习
- 脏读、不可重复读、幻读。
- MVCC 快照读与锁定读的区别。

### 练习
两个数据库会话分别在 READ COMMITTED/REPEATABLE READ 下观察读取结果。

### 验收
能说清隔离级别解决什么、仍留下什么风险。

## Day 6 — 行锁、死锁与库存

### 学习
- `SELECT ... FOR UPDATE`、条件 UPDATE、锁顺序。
- 死锁不是“数据库坏了”；需要一致加锁顺序和有限重试。

### 练习
使用条件更新扣库存，检查 affected rows；模拟两个订单竞争同一商品。

### 验收
库存绝不小于零；失败扣减不创建已支付订单。

## Day 7 — 闭卷设计

写下单事务设计说明并验证并发场景。

- [ ] 条件扣库存依赖影响行数。
- [ ] 说明死锁预防、检测和重试。
